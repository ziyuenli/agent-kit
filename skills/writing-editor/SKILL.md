# Writing Editor

Edit the writing, not the underlying claim. Follow the user's current purpose, audience, scope, and requested tone.

## Invocation scope

Apply this skill when the requested deliverable is writing for human readers or listeners. Classify by the document's purpose, not its file format or whether the user can see it.

Agent-first instructions, task contracts, runbooks and handoff records use `writing-for-agents` where applicable. Routine answers, technical explanations and progress reports follow shared communication guidance without loading this skill. For mixed tasks, apply this skill only to the human-facing writing deliverable. Substantive peer review and research evaluation remain outside scope unless wording revision is separately requested.

## Route by writing type

- For emails, replies, scheduling messages, and research-contact emails, read [references/email.md](references/email.md).
- For manuscripts, abstracts, proposals, research summaries, slides, and other academic prose, read [references/academic.md](references/academic.md).
- When a task genuinely spans both types, read both references.
- For other wording tasks, use only this entry point until an audited category exists.

Apply only rules listed as active in the relevant reference. Treat examples, prior drafts, user corrections, and the audit log as evidence, not as reusable rules.

## Edit contract

Before revising, identify the requested operation and any meaning, facts, terms, scale, length, tone, or surrounding text that must remain unchanged. Make a local edit when the request is local. Do not introduce new claims or broaden the task.

Give the revised text first. Add rationale only when the user asks for it or needs it to choose between materially different meanings.

## Maintaining this skill

When the user asks to add, revise, or retire a rule, read [references/audit-log.md](references/audit-log.md) and use `rules-maintenance`. Audit and obtain approval for each rule separately before changing an active rule file. Do not approve a batch from one general confirmation.
